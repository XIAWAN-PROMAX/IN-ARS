# IN-ARS 系统架构

## 1. 设计目标

IN-ARS 希望建立一个可扩展的 Agent-to-Robot 系统：上层 Agent 负责理解目标与规划任务，下层机器人系统负责状态感知、动作执行与反馈。架构不绑定单一 Agent 平台，也不把某一型号控制器视为唯一硬件。

## 2. 总体分层

1. **交互层**：接收自然语言、图形界面或预定义任务。
2. **Agent 层**：意图识别、任务拆解、上下文管理、必要时调用专用 Agent。
3. **任务规范层**：把自然语言转换为结构化任务，包含目标、参数、前置条件、限制、超时与完成条件。
4. **通信接入层**：IoT 主线路和 HRCU 特殊直连分支。
5. **本地执行与安全层**：校验命令、检查机器人状态、执行限制、超时与人工停止。
6. **控制器适配层**：把统一动作表达映射到经验证的具体控制器能力。
7. **反馈层**：汇总状态、结果、异常和必要的环境信息，返回 Agent。

## 3. 两条通信路径

### A. IoT 主线路

用户 → Agent → 任务规范化 → 权限与任务校验 → 中鸣 IoT 平台 → IoT 模块 → 本地执行与安全层 → 控制器适配层 → 机器人。

这是项目默认研究路径。平台地址：[中鸣 IoT 平台](https://iot.zmrobo.com/?lang=zh-CN)。

设备注册方式、消息协议、API、Topic、鉴权、消息时序和可控制能力，均须查阅官方资料并实测确认。

### B. HRCU Agent 直连特殊分支

用户 → Agent → 任务规范化 → 权限与任务校验 → HRCU 接入层 → 本地执行与安全层 → 控制器适配层 → 机器人。

此分支仅在 HRCU 确实提供可用且获授权的接入接口时成立。它不意味着可以绕过本地安全监督，也不预设接口类型。

## 4. 统一任务模型（概念）

建议任务对象至少包含：

- `task_id`：任务唯一标识
- `intent`：任务意图
- `target`：目标对象或区域
- `parameters`：经定义的参数
- `preconditions`：执行前置条件
- `constraints`：速度、范围、时长等限制
- `timeout`：任务超时策略
- `completion_criteria`：完成判定
- `status`：待处理、已校验、执行中、完成、失败或已取消

字段仅为架构建议，具体数据结构应随硬件能力和接口资料迭代。

## 5. Agent 协作建议

- **任务管理 Agent**：理解用户目标、拆分步骤、维护任务状态。
- **环境理解 Agent**：解释可用传感器或外部环境数据。
- **规划 Agent**：生成高层路线或动作计划。
- **执行监督模块**：不依赖语言模型作最终安全裁决，按确定性规则检查任务。
- **反馈分析 Agent**：总结执行结果并提出下一步建议。

Agent 的输出是候选任务，不是绕过安全层的直接硬件命令。

## 6. 关键架构约束

- 云端通信不承担实时运动控制闭环。
- 控制器差异由适配层封装。
- 不支持的动作必须明确拒绝，不得伪造成功状态。
- 网络中断、数据过期、状态不明时进入安全状态。
- 所有执行结果应可追踪，重要操作保留日志。
