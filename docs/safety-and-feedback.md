# 安全与反馈机制

## 1. 安全优先级

机器人本地安全机制优先级高于 Agent 任务目标。远程 Agent、IoT 平台消息或网络服务不得直接驱动实时电机控制闭环。

## 2. 指令生命周期

1. 接收：获取用户请求或上层任务。
2. 理解：Agent 生成结构化任务候选。
3. 校验：检查任务格式、权限、参数范围、设备状态和任务时效。
4. 批准：仅将已支持且符合规则的任务交给本地执行层。
5. 执行：由控制器适配层调用经确认的能力。
6. 反馈：返回执行状态、结果和异常。
7. 结束：完成、失败、超时或取消均形成明确状态。

## 3. 失败处理

- 网络中断：停止接收新的远程任务；本地按预先定义的安全策略处理当前状态。
- 消息重复：通过任务标识和去重机制避免重复执行。
- 消息过期：拒绝过期任务。
- 状态未知：不继续依赖不确定状态执行新动作。
- 传感器异常：停止相关自主动作并提示检查。
- 超时或异常：记录原因并进入预设安全状态。

具体安全状态必须结合机器人结构、官方说明和测试环境制定。

## 4. 人工监督

研究和测试阶段应由具备相应知识的人员在场监督，保留容易触达的停止方式，并在空旷、隔离、低风险环境中开展验证。不得在人员密集或存在碰撞风险的区域测试自主运动。

## 5. 数据与凭据

- API 密钥、设备令牌、密码不得提交到 Git 仓库。
- 使用环境变量或受保护的密钥管理方式。
- 日志避免记录敏感凭据和不必要的个人信息。
- 为设备与 Agent 设置最小必要权限。
- 定期检查访问权限并撤销不再使用的凭据。

## 6. 反馈数据建议

任务 ID、设备标识（非敏感形式）、时间戳、任务状态、执行结果、错误类别和必要的传感器摘要。反馈数据应有明确用途与保留策略。
