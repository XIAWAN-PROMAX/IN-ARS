# 接入方式研究

## 1. 目标

验证 Agent 平台如何与中鸣 IoT 平台、物联网模块及 HRCU 建立受控的数据与任务通道。本文不提供未经确认的 API、密钥、Topic 或协议参数。

## 2. IoT 主线路研究流程

1. 阅读中鸣 IoT 平台官方说明，确认账号、设备注册与授权模型。
2. 确认目标物联网模块的型号、固件版本、联网方式和可用功能。
3. 从官方资料确认平台是否提供 API、消息订阅/发布能力或其他集成方式。
4. 记录消息格式、身份认证、权限范围、限流、超时、重试和错误码。
5. 先做只读状态验证，再在安全、低风险环境中验证受控任务。
6. 将平台通信封装为独立适配器，避免 Agent 直接依赖平台细节。

官方入口：
- https://iot.zmrobo.com/?lang=zh-CN
- https://zmrobo.com

### 待确认项目

| 项目 | 需要确认的内容 |
|---|---|
| 设备接入 | 设备注册、绑定、在线状态 |
| 通信机制 | 官方支持的 API、消息协议或 SDK |
| 消息模型 | 上下行格式、字段含义、确认机制 |
| 身份权限 | 设备身份、用户权限、令牌生命周期 |
| 可靠性 | 超时、重试、去重、离线处理 |
| 数据反馈 | 状态、事件、错误与时间戳 |

MQTT、Topic 等只能作为待核实的候选技术方向，不能在未确认时当作平台既定能力。

## 3. HRCU Agent 直连分支

需要先确认：
- HRCU 的官方编程与通信接口；
- 是否允许第三方 Agent 平台接入；
- 接口运行位置、认证方式和权限边界；
- 能否读取状态、提交高层任务及接收执行反馈；
- 接入是否需要官方软件、网关或特定固件。

若无官方支持接口或无法安全验证，则保留为研究方向，不宣称已实现。

## 4. 控制器适配

对 E6、E7、HRCU、M6、M5 分别建立能力档案：
- 官方型号与版本信息；
- 支持的输入输出与通信方式；
- 可用传感器与执行部件；
- 官方开发工具与编程环境；
- 已验证的高层动作；
- 已知限制和未解决问题。

## 5. 接入决策

优先选择官方支持、权限清晰、可读取执行状态且便于本地安全校验的路径。任何路径都必须经过统一任务规范层与本地安全层。
