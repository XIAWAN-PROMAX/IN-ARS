# IN-ARS 项目路线图

项目按阶段推进；每阶段先完成资料与验证，再进入下一阶段。所有能力以实际测试结果为准。

## Phase 0 — 理论与资料整理
- [ ] 明确系统边界和统一任务模型
- [ ] 收集中鸣控制器与 IoT 官方资料
- [ ] 建立接口、权限和能力差异表
- **交付物：** 架构文档、资料清单、风险清单

## Phase 1 — Agent 原型
- [ ] 选择一个 Agent 平台进行概念验证
- [ ] 实现自然语言到结构化任务的转换
- [ ] 建立任务状态与反馈格式
- **交付物：** 不连接真实执行机构的任务原型

## Phase 2 — IoT 通信验证
- [ ] 按官方流程完成设备与平台接入
- [ ] 先验证只读状态和消息往返
- [ ] 验证认证、超时、重试与断网行为
- **交付物：** IoT 接入验证报告

## Phase 3 — 控制器适配
- [ ] 逐一研究 E6、E7、HRCU、M6、M5
- [ ] 明确各型号可用能力与限制
- [ ] 在受控环境验证有限的高层任务
- **交付物：** 控制器能力矩阵与适配记录

## Phase 4 — HRCU 直连研究
- [ ] 确认官方接口是否支持
- [ ] 验证 Agent 接入、认证和反馈
- [ ] 与 IoT 主线路保持一致的安全规则
- **交付物：** 可行性报告；若不支持则记录限制

## Phase 5 — 感知与自主能力
- [ ] 确认传感器与数据质量
- [ ] 研究定位、地图、规划和障碍物检测
- [ ] 在受控环境验证感知—规划—执行—反馈闭环
- **交付物：** 自主能力验证报告

## Phase 6 — 系统集成
- [ ] 集成任务管理、接入层、执行层和反馈层
- [ ] 测试异常、权限、取消与人工停止
- [ ] 完成文档、版本记录与已知限制说明
- **交付物：** 可复现的系统原型与技术报告

## 里程碑原则

不以“演示成功”代替可靠性验证。每个阶段都应记录软硬件版本、测试环境、预期结果、实际结果、异常与未解决问题。
